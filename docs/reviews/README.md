**Owner threat-model decision (2026-09-14).** Asked whether IDea should defend its truth corpus against a deliberately hostile program
running as the owner on his own PC (hand-editing the corpus manifest, racing file or junction swaps, ignoring the
advisory lock), the owner chose to treat that as **out of scope** for the local tool. Follow-up reviews therefore
classify findings as **realistic** (reachable by accident as one local Windows user: re-running a command, tidying a
folder, a crash, a crash-looping worker, a quick cancel, two tabs, a price change, an existing queue or corpus) or
**[adversarial]** (needs a hostile same-user process). A cycle is OK to commit with zero realistic P0 or P1 findings;
adversarial findings are recorded in each cycle's record as accepted residual risks rather than hardened against.
This decision was put about the truth corpus: an adversarial-only finding that could still spend or lose real AudD
credit is raised with the owner rather than accepted automatically. It is to be revisited if IDea is hosted for other
people. On 2026-09-15 the owner explicitly accepted the money follow-up's two adversarial money risks; see its record.
